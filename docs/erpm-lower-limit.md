# Нижня межа eRPM у телеметрії DShot

Чому відповідь не може повідомити оберти, нижчі за ≈ 918 eRPM, і що саме передається, коли мотор крутиться повільніше. Доповнення до кроку 2 у `reply-waveform-0x5F4.md`.

> **Коротко.** Найбільше 12-бітне значення `0xFFF` зарезервоване під «мотор стоїть». Тому найповільніше, що FC ще бачить як оберти, — це `0xFFE` ≈ 919 eRPM. Усе, що повільніше (≤ 917 eRPM), кодується як `0xFFF`.

## Звідки береться межа

Період зберігається як `m << e`: 3 біти експоненти `e` (0…7) і 9 біт мантиси `m` (0…511). Найбільше значення, яке вміщується в ці 12 біт:

```
e = 7, m = 511  →  e12 = (7 << 9) | 511 = 0xFFF
період = 511 << 7 = 65 408 мкс
eRPM   = 60 000 000 / 65 408 ≈ 917
```

Але `0xFFF` водночас домовлене значення «мотор стоїть», і FC читає його як 0 об/хв, а не як 917 eRPM. Тому останнє «справжнє» значення — на один крок менше:

| e12 | e | m | період | eRPM | FC бачить |
|---|---|---|---|---|---|
| `0xFFD` | 7 | 509 | 65 152 мкс | ≈ 921 | 921 eRPM |
| `0xFFE` | 7 | 510 | 65 280 мкс | ≈ 919 | **919 eRPM — найповільніше** |
| `0xFFF` | 7 | 511 | 65 408 мкс і довше | ≤ 917 | **стоїть (0)** |

## Як `encode_period()` доходить до `0xFFF`

Повільний мотор потрапляє в `0xFFF` двома шляхами:

```rust
fn encode_period(period_us: u32) -> u16 {
    if period_us == 0 {
        return 0x0FFF;           // (а) період невідомий
    }
    let mut m = period_us;
    let mut e = 0;
    while m > 0x1FF {
        m >>= 1;
        e += 1;
    }
    if e > 7 {
        return 0x0FFF;           // (в) період ≥ 65 536 мкс
    }
    ((e << 9) | m) as u16        // (б) 65 408…65 535 мкс → e = 7, m = 511 = 0xFFF
}
```

| Період, мкс | eRPM | Що відбувається | e12 |
|---|---|---|---|
| 65 280…65 407 | ≈ 919…917,3 | `e = 7, m = 510` | `0xFFE` |
| 65 408…65 535 | ≈ 917,3…915,5 | `e = 7, m = 511` — збігається з маркером (б) | `0xFFF` |
| ≥ 65 536 | ≤ 915,5 | після 8 зсувів `e > 7` (в) | `0xFFF` |
| 0 | — | ESC не виміряв період (а) | `0xFFF` |

Випадок (б) окремо обробляти не треба: обчислене значення само збігається з маркером.

Через округлення (кожен зсув відкидає молодший біт) межа між `0xFFE` і `0xFFF` проходить по періоду 65 408 мкс, тобто ≈ 917,3 eRPM. Тому «≈ 918 eRPM» — це межа, а 919 eRPM — найменше значення, яке FC реально може показати.

## Скільки це в механічних обертах

eRPM = механічні об/хв × кількість пар полюсів. Для типових моторів:

| Мотор | Пар полюсів | 917 eRPM ≈ механічних об/хв |
|---|---|---|
| 12N14P (14 магнітів) | 7 | 131 |
| 9N12P (12 магнітів) | 6 | 153 |

Гвинт на таких обертах ледь повертається, а робочі оберти дрона — від кількох тисяч до десятків тисяч об/хв. Тож на практиці межа нічого не обмежує: нижче за неї мотор або зупиняється, або ще розкручується після старту.

## Що це означає для нашого стенда

- Коли мотор стоїть або ESC ще не виміряв період, віддаємо `encode_reply(0x0FFF)`. Так і зроблено в кроці 6.3 плану: `sm.tx().push(encode_reply(0x0FFF))` перед першим кадром.
- Справжні ESC зазвичай роблять так само: якщо комутацій немає, вони відповідають `0xFFF`.
- Якщо на стенді імітувати оберти з газу (крок 8 плану), модель `1000 + throttle * 20` ніколи не опускається нижче 1000 eRPM, тож `0xFFF` з'явиться лише там, де період задано 0.

## Уточнення до `reply-waveform-0x5F4`

У кроці 2 там написано: «Найбільший можливий період: 511 << 7 = 65 408 мкс, тобто ≈ 917 eRPM. Повільніше мотор вважається зупиненим». З цього може здатися, що 65 408 мкс — ще валідне значення. Точніше так: 65 408 мкс — це вже `0xFFF`, тобто «стоїть», а найповільніше валідне значення — `0xFFE` ≈ 919 eRPM.
