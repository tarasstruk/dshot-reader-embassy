# Газ у кадрі DShot: звідки береться і що означає

Що лежить у полі `throttle` кадру, який приймає наш RP2040, хто і як його обчислює і чому це не «оберти» і не «відсотки». Доповнення до етапів A–C у `action-plan.md`.

> **Коротко.** Газ у кадрі — це 11-бітна **команда потужності** для одного мотора: 48 означає «мінімум», 2047 — «максимум». Значення обчислює FC окремо для кожного мотора, змішуючи стик пілота з корекціями стабілізації. Скільки обертів вийде насправді, залежить від мотора, батареї й гвинта, тому FC і просить ESC повідомити eRPM у відповіді.

## 1. Будова кадру

Кадр — 16 біт:

```
 біти 15…5      біт 4   біти 3…0
 ggggggggggg    T       cccc
 газ (11 біт)   телем.  CRC (інвертована в двонапрямному режимі)
```

Приклад з плану: `0x7D05`

```
0111 1101 000 | 0 | 0101
газ = 1000      T   CRC
```

У коді: `decode_frame(raw)` повертає `Frame { throttle, telemetry }`; газ — `frame >> 5`, біт T — `(frame >> 4) & 1`.

## 2. Діапазони значень

11 біт дають 0…2047, але значення поділено на дві частини:

| Значення | Що означає | У коді |
|---|---|---|
| 0 | «мотор стоп»: FC не озброєний (disarmed) або мотор вимкнено | `is_command()` = true |
| 1…47 | спеціальні команди: біп, запит версії, напрямок обертання, збереження налаштувань ESC тощо | `is_command()` = true |
| 48…2047 | газ: 48 — мінімум, 2047 — максимум, 2000 кроків | `is_command()` = false, `THROTTLE_MIN = 48`, `THROTTLE_MAX = 2047` |

Команди FC надсилає лише тоді, коли мотори не крутяться, і зазвичай повторює одну команду кілька кадрів поспіль, щоб ESC її точно прийняв.

## 3. Звідки FC бере газ

Один кадр — це газ **одного** мотора. У квадрокоптера чотири окремі проводи, на кожному свій кадр зі своїм значенням. Наш RP2040 під'єднаний до одного виходу (наприклад, M1) і бачить лише його.

Ланцюжок у FC:

```
стик газу пілота ─┐
                  ├─► мікшер ─► вихід мотора 0…1 ─► масштаб у 48…2047 ─► кадр DShot
PID-регулятор ────┘   (на кожен мотор свій)
(стабілізація кутів)
```

1. **Стик пілота** задає загальну тягу — однакову для всіх моторів.
2. **PID-регулятор** порівнює бажане і виміряне гіроскопом положення і додає кожному мотору поправку: щоб нахилитися вперед, задні мотори отримують трохи більше, передні — трохи менше.
3. **Мікшер** складає це для кожного мотора і дає вихід від 0 до 1.
4. **Масштабування:** вихід 0…1 перетворюється на 48…2047. Нижня межа — не 48, а трохи вище: це **холостий хід** (`dshot_idle_value`, за замовчуванням 5,5 %), тобто ≈ 48 + 1999 × 0,055 ≈ **158**. Озброєний дрон з опущеним стиком тримає мотори на цьому значенні, щоб вони не зупинялися.
5. Цикл повторюється з частотою PID-циклу (у нашому налаштуванні 4 кГц): кадр за кадром газ змінюється, навіть коли стик нерухомий, бо PID постійно коригує.

Тому навіть при сталому стику значення `thr` у виводі `tio` «тремтить» на кілька одиниць. Це нормально, якщо FC озброєний і гіроскоп бачить рух.

## 4. Що газ означає фізично

Газ — це **замовлена потужність**, а не оберти:

- ESC перетворює газ на коефіцієнт заповнення ШІМ на фазах мотора: приблизно «яку частку напруги батареї подати».
- Оберти, які з цього вийдуть, залежать від KV мотора, напруги батареї (вона просідає під навантаженням) і гвинта: з гвинтом і без нього той самий газ дає дуже різні оберти.
- Без навантаження грубо: оберти ≈ KV × напруга × частка газу. Під навантаженням гвинта — помітно менше і нелінійно.

Саме тому двонапрямний DShot і існує: FC хоче знати **справжні** оберти кожного мотора, а не вгадувати їх з газу. Betaflight використовує eRPM для RPM-фільтра (вирізає з даних гіроскопа шум на частоті обертання моторів) і для динамічного холостого ходу.

## 5. Звідки газ на стенді, без польоту

На стенді дрон не літає, тож газ задають інакше:

| Спосіб | Що бачить RP2040 |
|---|---|
| FC не озброєний | 0 («мотор стоп») у кожному кадрі |
| вкладка **Motors** у Betaflight Configurator, режим тесту моторів (без гвинтів!) | повзунок 1000…2000: 1000 → 0 («стоп»), 1001…2000 → ≈ 48…2047 лінійно |
| озброєний FC, стик газу | холостий хід ≈ 158 і вище, плюс поправки PID |
| команди з CLI або Configurator (біп, запит версії) | значення 1…47 |

Найзручніше для перевірки етапів A–C — **тест моторів**: значення задається повзунком напряму, без PID і без озброєння. Наприклад, `thr=1000` у виводі `tio` (кадр `0x7D05`) відповідає повзунку ≈ 1477.

## 6. Що з цього для нашого стенда

- **Етап A:** `thr` має збігатися з повзунком (за формулою вище), `cmd=1` — лише для 0…47.
- **Етап C:** модель «eRPM = 1000 + газ × 20» з кроку 8 плану — лише іграшка для стенда, щоб FC бачив оберти, що змінюються з газом. Справжній ESC повідомляє виміряні оберти, і вони від газу залежать нелінійно.
- **Обережно з динамічним холостим ходом** (`dyn_idle_min_rpm` у Betaflight): він підвищує газ, якщо eRPM нижче порогу. Якщо стенд відповідає вигаданими обертами, FC може почати «підкручувати» газ у відповідь на них — вийде петля зворотного зв'язку з нашою моделлю. На стенді краще вимкнути (`dyn_idle_min_rpm = 0`) або тримати модель вище порогу.
- **Біт T** у двонапрямному режимі нашій відповіді не потрібен: eRPM відповідаємо на кожен кадр незалежно від T. Він стосується розширеної телеметрії окремим проводом (через UART), якої в нас немає.

> Деталі Betaflight (холостий хід 5,5 %, відображення повзунка 1000…2000 у 48…2047, `dyn_idle_min_rpm`) наведено за типовими налаштуваннями й можуть відрізнятися між версіями. На стенді звіряйте з виводом `tio`: він показує, що FC насправді надсилає.
